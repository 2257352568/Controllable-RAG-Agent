# 从零理解这个项目

先不用背 LangGraph、FAISS 或评测指标。把项目当作一个“先查书、再回答”的助手，按下面顺序理解即可。第一次学习建议控制在 30 分钟：前三步各 5 分钟，第四步 10 分钟，最后 5 分钟回答三个小问题。

## 第一步：为什么要查资料

直接问模型，它可能凭训练时记住的内容回答，但我们不知道答案是否来自这本书。普通 RAG 先从书中检索片段，再把片段交给模型回答；能给出出处，也可以在资料不足时拒答。这是 `direct` 和 `naive-rag` 的区别。

**看完能回答：** 为什么模型答对了，也可能不算这个项目答对了？

## 第二步：Agent 多做了什么

普通 RAG 通常只检索一次。这个项目的 Agent 会先规划任务，选择正文、章节摘要或原文摘录作为来源，检索后判断证据是否足够；足够则回答并引用，不足则决定继续检索或停止。主图在 `controllable_rag/graph.py`，各步骤的实现主要在 `controllable_rag/nodes.py`。

这不代表 Agent 一定更好。它多调用模型，可能更慢、更贵，也可能在复杂问题上循环或耗尽预算。

**看完能回答：** Agent 相比普通 RAG，多做了什么决定，又付出了什么代价？

## 第三步：项目怎样检验自己

`evaluation/run_evaluation.py` 用同一问题比较三条路径：`direct`（不查书）、`naive-rag`（查一次）、`agentic-rag`（规划与按证据决策）。52 道题已经人工核对过答案和语料依据；这只是题目质量，不是系统正确率。当前正式固定模型评测未完成，已有分层结果反而显示 Agent 弱于普通 RAG。

两题的最小演示见 `docs/interview/evidence/MINIMAL_DEMO_2026-09-17.md`：有证据题三条路径都答对；无证据题 direct 使用语料外知识作答，普通 RAG 和 Agent 拒答。另一个多跳题仍因 Token 预算耗尽。这些都是小样本事实，不能写成整体效果提升。

**看完能回答：** 为什么项目保留失败结果，而不是只展示成功截图？

## 第四步：怎样亲手看一遍

先看 `README.md` 的“核心流程”图，再打开 `controllable_rag/graph.py`，只找三个位置：入口、检索后去哪、什么时候结束。暂时不用读完全部节点。想看界面时按 README 启动 `simulate_agent.py`；想看最小评测结果时先读上面的证据文件，不必立刻重新调用模型。

**完成标准：** 能沿着流程图指出“提问—检索—判断—回答/停止”，不要求解释每个函数。

读完后只回答三个小问题，能用自己的话说清即可：

1. 直接问模型与先查书再回答，有什么区别？
2. Agent 比普通 RAG 多了哪一步判断？
3. 为什么“Agent 跑得起来”不等于“Agent 更好”？

这三题能回答后，再去 `docs/interview/README.md` 练最先列出的六个面试问题。当前不要求你讲脱稿项目介绍，也不把阅读这页当成口述验收。
