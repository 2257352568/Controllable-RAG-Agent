# 简历项目条目：Controllable RAG Agent

这份文件只提供可以由当前仓库证据支持的表述。简历控制在 3–4 条，不把 README 的所有技术
细节搬进去；每个关键词都应能承受连续追问。

## 当前证据支持的内部草稿

这版可以用于组织措辞和模拟面试，但项目尚未通过 `ROADMAP.md` 的学习型简历最低验收。
没有个人仓库链接时，不要把上游仓库写成个人项目链接；没有同模型正式对照时，不增加任何
效果提升数字。52/52 题已人工审核，现有分层结果显示 Agent 弱于 naive RAG。

> **可控 Agentic RAG 问答与评测**  
> Python / LangGraph / FAISS / FastAPI

- 基于开源 LangGraph 工作流梳理“规划—多源检索—证据判断—回答/拒答”闭环，接入百炼模型
  与正文、摘要、引文三类 FAISS 索引，支持按来源和预算控制检索过程。
- 完善逐句证据引用与不足证据时的停止路径，记录节点耗时、模型调用和终止原因；通过
  FastAPI/SSE 提供查询结果及过程进度。
- 建立 Direct、Naive RAG、Agentic RAG 三路径对照，人工审核 52 条题目；保留模型版本、
  成本与失败记录，定位多跳问答中的检索空转和预算耗尽问题。

### 为什么这版措辞有证据支持

- 上游提供原始 LangGraph 工作流和示例语料；本条目只把本地模型迁移、证据/预算/Trace、
  评测与工程改动写为个人工作，来源与改动清单在 README 明示。
- 所有动词均有代码、测试或小样本探针支持。
- 没有把 213 项离线测试写成模型质量，也没有把模型分层结果拼接成正式准确率。
- 最后一条主动暴露评测边界，适合引出“如何证明 Agent 值得复杂度”的追问。

## 更短的三条版本

适用于简历空间紧张的情况：

- 梳理开源 LangGraph RAG 工作流，接入百炼模型和三类 FAISS 索引，形成规划、检索、证据判断与回答闭环。
- 完善逐句引用、证据不足拒答及预算控制，通过 FastAPI/SSE 展示结果和过程。
- 人工审核 52 题并建立三路径对照，复盘多跳失败与调用成本，不虚构效果提升。

## 与第二个企业采购项目的区分

两项目不应写成重复的“LangGraph + 多 Agent”技术栈展示：

| 项目 | 核心叙事 | 主动强调 | 留给另一个项目 |
|---|---|---|---|
| Controllable RAG Agent | RAG 质量、证据、评测与可控性 | 多粒度检索、grounding、三基线、预算与失败复盘 | ERP 业务流、MCP、企业审批、多智能体协作 |
| 企业采购助手 | 自然语言驱动采购全流程 | 业务 Agent 协作、工具协议、事务/审批与系统集成 | 深入的 RAG 评测方法与引用实验 |

第一项目应证明“理解 Agentic RAG 何时有效、怎样验证和控制”；第二项目证明“能把 Agent
接入企业流程”。这种分工比两个项目都罗列同一批框架更容易形成互补。

## 禁止出现的表述

- “从零原创”“自主研发完整架构”。
- “准确率提升 X%”“显著降低幻觉”，除非正式门禁和独立复验已经通过。
- “生产级”“企业级高可用”“支持分布式部署”。
- “使用 OpenAI 模型”；项目使用的是 Qwen，`langchain-openai` 只是兼容接口客户端。
- 把 213 项离线测试、11 条检索冒烟或单条成功回答写成业务准确率。
