# 评测重试分类契约（2026-09-12）

## 问题

旧实现会对 `evaluate_case` 捕获的所有异常执行相同指数退避，包括不会自行恢复的 schema、鉴权和参数错误。这既浪费额度，也会延迟暴露根因。

## 当前策略

- 可重试：连接/读写/连接池超时等瞬时网络异常，以及 HTTP 408、409、425、429、500、502、503、504。
- 不重试：HTTP 400、401、403、404、405、422，以及默认未知或本地契约异常。
- 沿异常 `__cause__` / `__context__` 查找被 SDK 包装的网络根因。
- 结果记录 `attempts`、`error_class`、`retryable`；汇总记录平均尝试数、发生重试比例和重试恢复率。

## 验证

- 503 首次失败、第二次成功：调用两次且只退避一次。
- `ValueError`：即使配置两次重试也只调用一次。
- 429、400 和未知本地异常分类测试。
- 汇总测试验证 retry rate、recovery rate 和 error class 计数。
- 全套 117 项离线测试、两套数据审计和 `git diff --check` 通过。

## 边界

这是评测执行器的外层重试，当前仍会重跑整个系统调用；供应商 SDK 内部 HTTP attempts 也不可见。生产方案应进一步下沉到幂等节点，加入 jitter、总 deadline、熔断和 checkpoint。
