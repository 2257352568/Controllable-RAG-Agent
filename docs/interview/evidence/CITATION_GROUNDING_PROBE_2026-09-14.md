# 引用归因检查修复（2026-09-14）

## 故障与根因

答案包含 A 文档中的事实，却只选择 B 文档作为引用。旧实现先对白名单 ID 求交，随后
将包含 A、B 的完整上下文交给 grounding 模型。即使裁判正确判断了“答案在上下文里有
依据”，也没有验证“已选引用能支持答案”。检索蒸馏阶段同样会将错误归因继续向后传递。

修改前新增两项确定性测试，单跳引用错配、多跳缺前提在 answer/distillation 两阶段共
产生 4 个失败断言。这是代码上下文范围的缺陷，无须依赖模型随机输出来复现。

## 修复范围

- 蒸馏阶段按所选 ID 回查 `retrieved_evidence` 原始记录，仅将这些记录交给裁判。
- 答案阶段按所选 ID 回查 `evidence_records` 原始记录；不再使用累计蒸馏文本作最终依据。
- 所选引用不存在或内容为空时直接失败，不产生额外裁判请求。
- 沿用有限重试；错误蒸馏不进入累计上下文，答案最终失败以 `grounding_failed` 拒答。
- Prompt 版本为 `2026-09-14.1`，要求所选证据共同覆盖全部事实/推理前提，且每个所选
  来源支持至少一个实质性事实。语义判定仍由模型完成，未实现逐 claim 的结构化映射。

## 可复现命令

```powershell
venv\Scripts\python.exe -m unittest tests.test_citation_grounding -v
venv\Scripts\python.exe evaluation\run_citation_grounding_probe.py
```

第二条命令会调用已配置的千问模型。本次使用 `qwen3.8-max`、temperature=0、
max_output_tokens=2000、SDK retries=5、timeout=60s。逻辑调用上限 16、Token 上限
20,000、调用前累计 deadline 180s；没有 Embedding 调用，也没有修改索引或人审记录。
